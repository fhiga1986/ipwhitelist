What is a user agent checker?

A user agent is a string that your browser sends with every HTTP request, identifying itself to web servers. It includes information about your browser name and version, operating system, and rendering engine. Web servers use this to serve appropriate content, while developers use it for analytics, compatibility testing, and debugging.

A user agent checker simply shows you that string — and, as this page does, decodes it into browser, engine and OS, and adds the newer Client Hints values that modern browsers send instead of detailed user agent strings.

Anatomy of a user agent string

A typical Chrome user agent on Windows looks like: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36. Every token is a historical artifact of browser compatibility:

TokenWhat it really means
Mozilla/5.0Nothing. Every browser claims to be Mozilla so that 1990s servers would send it the "advanced" version of a page.
(Windows NT 10.0; Win64; x64)Platform. Since 2023 Chrome freezes this to Windows NT 10.0 even on Windows 11, and Android phones report Android 10; K regardless of model.
AppleWebKit/537.36 (KHTML, like Gecko)Engine lineage: Chrome's Blink engine forked from WebKit, which descends from KDE's KHTML, and all of them wanted pages built for Firefox (Gecko).
Chrome/130.0.0.0The actual browser and its major version. Minor and build numbers are zeroed by user agent reduction.
Safari/537.36Compatibility token so that sites sniffing for Safari keep working. Edge adds Edg/130, Opera adds OPR/, Brave sends an unmodified Chrome string.

Why would I need my user agent?

  • Bug reports. "It doesn't work" becomes actionable when you paste the exact browser, version and OS — copy the raw string above into the ticket.
  • Compatibility testing. Confirm that a device really runs the browser version your product supports, or that a user agent override in DevTools took effect.
  • Analytics sanity checks. Verify how your own browser appears in Google Analytics or your server logs before filtering bots or segmenting by device.
  • API clients and scrapers. Many APIs reject requests with an empty or default library user agent; sending a descriptive one (MyApp/1.2 (+https://example.com)) is good manners and often required.
  • Privacy awareness. The user agent plus screen size, timezone and language form a fingerprint that can identify you across sites without cookies — this page shows the same values a tracker would collect.

User agent reduction and Client Hints

Because user agent strings leaked so much detail, Chromium-based browsers (Chrome, Edge, Opera, Brave, Samsung Internet) reduced them in 2023: the OS version, device model and browser minor version are now fixed placeholders. Firefox and Safari apply similar freezing. If this page says "Windows 10/11" or "Android 10", that is why — the string no longer contains the real value.

The replacement is User-Agent Client Hints: low-entropy values (brand, major version, platform, mobile) are sent with every request as Sec-CH-UA headers, and high-entropy values (full version, platform version, model, architecture) are only available on request through navigator.userAgentData.getHighEntropyValues(), which is what the Client Hints cells above use when your browser supports it. Firefox and Safari do not implement Client Hints, so those cells stay empty there.

Common user agent strings by browser

Every major browser sends a distinct user agent string. Chrome on Windows typically includes "Chrome/VERSION" and "Safari/537.36" for compatibility. Firefox uses "Gecko/20100101 Firefox/VERSION". Safari on macOS uses "Safari/VERSION" without a Chrome token. Mobile browsers include "Mobile" in the string, and iPad Safari reports itself as a Mac unless you request the mobile site.

Web servers and APIs often use user agent parsing to serve different content to mobile vs desktop users, block bots, and apply browser-specific workarounds. For feature decisions, prefer feature detection (if ('serviceWorker' in navigator)) over user agent sniffing — strings lie, are frozen, and are trivially spoofed.

How to change your user agent for testing

In Chrome: open DevTools (F12) → three-dot menu → More tools → Network conditions → uncheck "Use browser default" under User agent → select or type a custom string. This lets you test how your website renders for different browsers and devices without changing your actual browser. Reload this page afterwards and the raw string above will show your override.

In Firefox: type about:config in the address bar → search for general.useragent.override → create a new string value with your desired user agent. In Safari: enable the Develop menu in Settings → Advanced, then Develop → User Agent.

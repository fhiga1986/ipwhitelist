What are HTTP headers?

HTTP headers are key-value pairs sent between clients (browsers) and servers with every HTTP request and response. Request headers tell the server about the client — its browser, accepted languages, cookies, and authentication tokens. Response headers tell the browser how to handle the content — caching rules, content type, security policies, and CORS settings.

Headers are invisible to users but decide a surprising amount of behaviour: whether a page may be embedded in an iframe, how long a CDN keeps a file, which origins may call an API, and whether the browser will ever load the site over plain HTTP again.

Why do security headers matter?

Security headers protect your web application from common attacks. Missing or misconfigured security headers are one of the most common findings in penetration tests, and the cheapest to fix — most are a single line of server configuration. What this tool can and cannot see from a browser

  • Your request headers are captured by sending a request from your browser to a public echo service (httpbin.org) and displaying what arrived. They are real, but they come from a cross-origin fetch(): a normal page navigation additionally sends Cookie, Accept: text/html… and Sec-Fetch-Mode: navigate.
  • Response headers of another site are only readable when that site allows cross-origin requests (CORS). Without an Access-Control-Allow-Origin header the browser hides the response entirely, and even with it, only a safelisted subset is exposed unless the server adds Access-Control-Expose-Headers.
  • Set-Cookie and Authorization are never exposed to JavaScript, by design.
  • For the full picture use your browser's DevTools (F12 → Network → click the request → Headers), curl -I https://example.com, or a server-side scanner such as securityheaders.com or Mozilla Observatory.

What is CORS and how do CORS headers work?

CORS (Cross-Origin Resource Sharing) headers control which external domains can make requests to your API or web service from a browser. The key headers are: Access-Control-Allow-Origin (which domains can access the resource), Access-Control-Allow-Methods (which HTTP methods are allowed), and Access-Control-Allow-Headers (which request headers are permitted).

CORS errors are one of the most common issues when building frontend applications that connect to APIs. The Response Headers tab shows the exact CORS headers returned by any URL that permits cross-origin reads, helping you diagnose cross-origin issues without needing to write test code.

FAQ

HTTP headers questions

Strict-Transport-Security (HSTS) is arguably the most critical — it forces all connections to use HTTPS and prevents SSL stripping attacks. For most sites, adding "Strict-Transport-Security: max-age=31536000; includeSubDomains" provides immediate security improvement. Content-Security-Policy is more complex to configure but provides the most comprehensive XSS protection.
Browser security (CORS) restricts which response headers JavaScript can access. A site has to opt in with Access-Control-Allow-Origin, and even then only a few safelisted headers are visible unless it also sends Access-Control-Expose-Headers. Some headers like Set-Cookie and Authorization are never exposed to JavaScript. To see all headers for a URL, use browser DevTools (F12 → Network tab) or a command-line tool like curl.
Request headers travel from your browser to the server and describe the client and what it wants: User-Agent, Accept-Language, Cookie, Authorization. Response headers travel back and describe the answer and how to treat it: Content-Type, Cache-Control, Set-Cookie and the security headers above. Some names, such as Content-Type and Content-Length, appear in both directions.
CORS (Cross-Origin Resource Sharing) is a browser security mechanism that controls which origins can make requests to your API. The Access-Control-Allow-Origin header tells browsers which domains are allowed to read your responses. Misconfigured CORS (like using wildcard * on authenticated endpoints) can expose sensitive data to malicious sites.
